### Key Findings

**Novelty (76→85%):** Polymarket-style markets + AMM/bonding-curve + staking are heavily documented in DeFi prior art. Novelty is most plausible in the exact structure of the "TeaBag/MAD Shield" loss-protection mechanism (reserve accounting, payout gating, anti-bank-run controls) and any multi-oracle dispute/commit-reveal resolution protocol if materially different from known designs.

**Non-Obviousness (77→86%):** A skilled DeFi engineer could combine known components. To clear §103, emphasis needed on non-obvious control architecture: solvency constraints, dynamic premium/coverage computation, two-phase reserve locking, manipulation-resistant resolution producing measurable technical effects.

**Subject Matter (85→90%):** Smart-contract protocols with concrete state transitions are generally eligible. Safest path: claim concrete protocol steps and data structures (reserve buckets, coverage tokens, settlement epochs, dispute windows) rather than outcomes like "improved retention."

**Claim Clarity (68→87%):** Terms like "TeaBag insurance," "triple threat oracle," and "story sagas" need precise technical definitions mapping to objective mechanisms: contract roles, functions, state transitions, measurable outputs.

### AI Drafting Recommendations
1. Convert branded features into precise technical modules with defined I/O and state transitions
2. Draft claims focused on loss-shield reserve-locking and payout gating protocol (not general prediction markets)
3. Add fallback embodiments: commit-reveal oracle resolution, dispute windows, solvency invariants, dynamic coverage pricing
4. Frame as technical control system with explicit solvency invariants and dispute-state transitions
5. Add concrete use-case examples (market lifecycle, settlement, shield payout)

### Patent-Worthy Core IP
- On-chain risk-shield reserve-locking protocol
- Dynamic premium computation (GARCH-based volatility oracle)
- Multi-tier oracle resolution with commit-reveal
- Anti-bank-run solvency controls (4.9% monthly burn cap)
- Two-phase reserve locking with settlement epochs
